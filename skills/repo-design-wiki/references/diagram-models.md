# 代码百科选图规则

先确定读者需要核对的是哪一种关系，例如系统边界、静态结构、运行顺序、数据变化、对象状态或部署位置。沿着本章 RQ 选一张图，只画能改变读者对这次交接理解的对象和关系。相邻章节可以使用同类图，各自解释不同的交接。

## 系统架构与部署

| 图型 | 读者问题 | 必需信息与核对位置 |
| --- | --- | --- |
| C4 系统景观图 | 整个组织或领域里有哪些系统，它们怎样协作？ | 系统、角色、跨系统关系。核对系统目录、集成文档与可见配置。 |
| C4 系统上下文图 | 谁使用本系统，它和哪些外部系统交互？ | 一个目标系统、使用者、外部系统和交互目的。核对公开入口、客户端与集成配置。 |
| C4 容器图 | 系统内部有哪些应用或数据存储，它们怎样通信？ | 系统边界、应用或数据存储、职责和通信方式。核对启动入口、服务配置与存储定义。 |
| C4 组件图 | 一个应用内部有哪些组件，职责和接口如何交接？ | 同一容器内的组件、职责、对外接口和依赖。核对模块入口、注册与装配。 |
| C4 代码图 | 一个组件由哪些类型或函数实现？ | 相关类、接口、函数及实现关系。核对定义、实现与使用点。 |
| C4 动态图 | 一个请求跨系统、应用或组件如何完成？ | 一个明确场景、相关架构元素和编号交互。用调用点核对顺序，用运行记录核对实际发生的路径。 |
| C4 部署图 | 在某个环境，应用或数据存储的实例运行在哪里？ | 环境、部署节点、制品或容器实例与连接。核对部署清单、基础设施定义和网络配置。 |
| 网络拓扑与信任边界图 | 流量经过哪些网络区段和信任边界？ | 网络区段、入口点、通信方向、协议以及边界上的控制。核对路由、网关和访问配置。 |

## UML 结构与行为

| 图型 | 读者问题 | 必需信息与核对位置 |
| --- | --- | --- |
| 类图 | 类型和接口如何关联、实现或继承？ | 关键类型、必要成员和关系语义。核对类型定义、接口实现与组合字段。 |
| 对象图 | 在一个具体输入、时点或测试用例里有哪些实例？ | 具体实例、关键属性值与实例链接。核对测试夹具、示例或运行记录。 |
| 包图 | 包、命名空间或层如何组织和依赖？ | 包边界、公开接口及依赖方向。核对导入、包清单和导出配置。 |
| 组件图 | 可替换组件提供或要求哪些接口？ | 组件、提供和所需接口及连线。核对接口定义、注册与装配。 |
| 组合结构图 | 单个类型或组件的内部部件如何通过端口协作？ | 类型边界、部件、端口、连接器。核对成员、端口声明和内部接线。 |
| 部署图 | 哪些制品部署在哪些节点、运行环境中？ | 节点、运行环境、制品和映射。核对制品定义与部署清单。 |
| Profile 图 | 项目用哪些构造型扩展 UML 元模型？ | Profile、构造型、被扩展的元类和约束。核对项目实际使用的建模定义。 |
| 用例图 | 某个角色能完成什么用户目标？ | 参与者、系统边界、目标及必要的包含或扩展关系。核对入口、权限、文档或验收测试。 |
| 活动图 | 动作如何分支、并发或汇合？ | 动作、控制流、判断和守卫条件。涉及并行时写清分叉与汇合，涉及责任时标出泳道。核对分支、异步调度与汇合逻辑。 |
| 状态机图 | 同一对象遇到什么事件会进入哪个状态？ | 对象、状态、触发事件及必要的守卫和动作。核对状态定义、转换代码和测试。 |
| 时序图（Sequence） | 一次具体场景里，谁先给谁发消息，谁等待或返回？ | 参与者生命线、按序消息、需要区分的同步或异步行为，以及影响结论的分支。核对调用点与处理端。 |
| 通信图 | 这个场景中哪些实例直接通信，交互次序如何？ | 对象、通信链接和编号消息。核对实例连接和消息发送位置。 |
| 交互概览图 | 多段交互如何串联、选择或并发？ | 交互片段、控制流和选择条件。核对发起各场景的编排代码。 |
| 定时图（Timing） | 某状态或值随时间怎么变化，有何时间约束？ | 时间轴、状态或值的变化、持续或截止约束。核对配置、协议或实测记录，并区分配置值与实测值。 |

## 实现、数据与工程过程

| 图型 | 读者问题 | 必需信息与核对位置 |
| --- | --- | --- |
| 流程图 | 一项操作经过哪些步骤，条件决定哪条路径？ | 步骤、判断、条件和结果。核对入口与控制分支。 |
| 泳道流程图 | 各角色或进程分别负责哪一步，在哪里交接？ | 按责任方分组的动作、条件、跨组交接。核对入口、处理器与编排。 |
| BPMN 流程、协作或编舞图 | 业务任务、事件和跨参与者的消息怎样推进流程？ | 流程视图画任务、事件和网关，协作视图补参与者和消息流，编舞视图强调参与者之间的交互顺序。核对工作流定义、事件处理和消息绑定。 |
| 数据流图（DFD） | 哪种数据从哪来，在哪里转换、传输和存储？ | 数据源、处理步骤、存储、接收方及具名数据流。核对格式定义、转换函数、生产和消费代码。 |
| 实体关系图（ERD） | 持久化实体如何关联，关系基数是多少？ | 实体、关系、基数及可选性。需要解释物理实现时加入相关主键、外键和约束。核对迁移与模型定义。 |
| 接口与消息结构图 | 请求、响应、事件或报文包含什么？ | 契约版本、层级、必填字段及必要的序列化布局。核对接口定义、schema、编码与解码代码。 |
| 数据血缘图 | 某个表、字段或制品如何由上游数据得出？ | 来源、转换、目标及该章需要跟踪的粒度。核对查询、映射和数据任务定义。 |
| 模块依赖图 | 哪个模块依赖哪个模块，依赖来自哪里？ | 同一层级的模块、依赖方向和依赖原因。核对导入、清单、接口声明或注入点。 |
| 调用图 | 这些函数或方法之间有哪些可确认的调用？ | 符号、调用方向、必要的分派条件。区分静态分析得到的可能路径和运行记录中的实测路径。 |
| 控制流图（CFG） | 一个函数内部的基本块如何跳转？ | 基本块、分支、回边和返回。核对编译器中间表示或实际控制语句。 |
| 语法树／中间表示结构图 | 代码、表达式或配置被解析成什么内部结构？ | 节点类型、父子关系、必要的绑定或转换。核对语法定义、构造代码和解析测试。 |
| 事件／消息拓扑图 | 事件由谁发布、经何通道路由、由谁消费？ | 生产者、主题或队列、路由条件、消费者。核对发布代码、订阅注册与消息配置。 |
| 任务依赖图（DAG） | 任务何时就绪，哪些前置条件必须满足？ | 任务、依赖方向、并行条件和交付物。核对编排定义、构建清单或调度配置。 |
| 构建、发布或迁移流程图 | 制品或数据如何逐步到达目标环境？ | 阶段、输入输出、验证和有证据的回滚路径。核对流水线、迁移脚本与运维文档。 |
| 页面或路由导航图 | 用户或客户端怎样从一个页面、路由或界面状态到另一个？ | 路由、触发动作和必要的访问条件。核对路由定义、导航调用与权限判断。 |
| 决策树 | 一组规则按什么顺序决定结果？ | 判定条件、优先级和叶节点结果。核对策略代码、配置和边界用例。 |
| 需求追踪图 | 某项要求由哪些逻辑实现、由什么测试验证？ | 可定位的需求、实现和验证关系。核对需求来源、源码与测试断言。 |
| 运行追踪／时间线 | 这一次执行耗时花在哪里，哪些工作并行？ | 运行实例、事件或 span、时间范围和因果关系。使用可核对的日志、trace 或测量记录。 |
| 版本演进图 | 版本、分支或提交如何合并、迁移？ | 有关的版本或提交、父子或合并关系和必要的变更点。核对 Git 历史、版本说明和迁移记录。 |

## 容易混淆的关系

- 流程图的箭头表示控制转移，数据流图的箭头表示数据移动，状态机图的箭头表示同一对象在事件触发下的状态转换。
- 静态依赖描述模块间的约束，调用图描述可能或观测到的调用，时序图描述一个选定场景的消息顺序。源码能确认的顺序和运行记录观测到的顺序分别说明。
- 类图说明代码类型关系，ERD 说明持久化实体和基数。C4 容器是应用或数据存储，Docker 容器与主机的对应关系放在部署图。
- 每张图限定层级、场景和环境。命名与正文一致，边标出动作、数据、条件或依赖方向，逐条核对支撑该关系的证据。只看到声明时，按声明说明，实测耗时和实际部署状态需要对应记录。

## DSH 当前输出规则

选图时参考完整目录。当前渲染器交付单层的有向节点和带标签的连线，图的标题应描述实际画出的关系。

| `diagram.kind` | 可交付的内容 |
| --- | --- |
| `flow` | 步骤、分支和交接。场景或流水线需要明确先后时，可把关键动作作为节点。 |
| `data` | 数据的生产、转换、存储和消费。连线写明载荷或变化。 |
| `dependency` | 系统、模块、类型、任务或部署对象之间的静态关系。连线写明依赖、实现、引用、部署或连接等关系。 |
| `state` | 同一实体在事件或条件触发下的状态转换。连线写明触发条件。 |

优先选当前格式能准确表达的关系。涉及生命线、并行泳道、时间轴、ER 基数、嵌套部署等专用结构时，用正文说明这些信息，图仅表示这套节点和连线确实能表达的子关系，按实际交付的图型填写 `kind`。每条连线引用当次读到的源码位置。模型和记法来源仅供选图，章节事实以当前仓库证据为准。
