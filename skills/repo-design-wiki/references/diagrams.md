# 图示指南

先写清读者看完图应该能回答什么。优先用短的真实符号和相邻说明，给显示尺寸有限的阅读区拆图。整仓文档一般用组件图说明静态分工，用时序、活动或数据流图说明一次执行，按需要补足其他关系。

| 要回答的问题 | 选图 | 需要核对的证据 |
| --- | --- | --- |
| 谁能触发什么用例，拿到什么结果？ | 用例图 | 实际参与者、入口、返回或可见结果 |
| 模块如何分工，如何跨边界交互？ | 架构图、组件图或依赖图 | 调用方和提供方、公开接口、依赖方向、数据或状态所有者 |
| 一次调用如何进行，哪一步先返回？ | 时序图 | 实际调用顺序、关键返回、异步交接、失败分支及最终观察点 |
| 条件如何影响处理结果？ | 活动图或流程图 | 真实判定、分支条件与各自出口，异常在哪传播或被吸收 |
| 什么事件改变状态？ | 状态图 | 初始状态、迁移条件、写入者、终态或幂等事件 |
| 输入在不同阶段长什么样？ | 数据流图 | 生产者、数据形状、变换、消费者，关键默认值在哪生效 |
| 数据或类型之间有哪些约束？ | 实体关系图或类图 | 实际实体、字段、关系基数，或真实继承、实现和组合 |
| 运行时有哪些进程和环境边界？ | 部署图 | 启动或部署定义、通信协议、存储位置，以及配置如何注入 |

## 接口和分支

- 组件图以 `调用方 → 提供方` 表示调用，以真实方法名、路由、事件名或协议标在连线上。需要同时解释静态依赖和时间顺序时分别用组件图和时序图。
- 图旁的接口说明应能独立阅读。复杂接口可用小表展示 `调用方 → 提供方`、实际入口、输入、返回或错误、状态影响与源码。小图可以用紧邻图的两三行说明。
- 区分同步回执、任务实际执行和持久化完成。把影响后续条件或调用方结果的返回画出来。每条不同结果的分支标出可判定条件。
- 让源码锚点和关系容易对应。将链接放在图的标题、对应图注或接口表中。节点上用短符号，长签名、字段结构和行号放到图外。

## 格式和呈现

- Mermaid 适合 Markdown 的流程、时序、状态与类型图。按语义选语法，检查节点标识、方向、引号、特殊字符、分组边界和闭合分支。可用现有渲染器时验证生成结果，并在阅读宽度内检查关键标签是否可读。
- 用户指定 HTML、SVG 或图片时，采用适合该输出的方式，优先保持图中文字可读，图旁保留可访问的说明及源码链接。宽图默认适应阅读宽度，密集内容按问题拆成数张完整的小图。
- 当前阅读器不能渲染图或缺少实际预览时，保留源码对应的简短说明，明确已做的是语法或静态检查。输出格式随交付需求选择。

## 代码百科存档模式的图示

- 优先采用阅读器可以直接绘制的基础语法。流程图和组件图用 `flowchart TD` 或 `flowchart LR`，节点写成 `A["入口"]`，条件写成 `B{"是否命中"}`，带标签的边写成 `A -->|读取| B`。
- 时序图用 `sequenceDiagram`、`participant A as 入口`、`A->>B: 请求` 和 `B-->>A: 返回`。复杂条件用图旁的分支说明或单独的流程图。状态图用 `stateDiagram-v2`，例如 `state "已排队" as Queued`、`[*] --> Queued` 和 `Queued --> [*]: 取消`。
- 每行放一条语句，节点 ID 用英文字母、数字或下划线，标签用简短纯文本。将接口细节、源码标记和图例放在围栏外。较密集的图可以拆成独立视图。
