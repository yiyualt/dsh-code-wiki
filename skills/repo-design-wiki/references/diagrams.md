# 图示指南

先确定读者想知道什么，再选对应的图。一张图回答一个问题。下面用办公 Agent 举例，实际制图时换成当前仓库中有源码证据的角色、输入和结果。

| 读者想知道什么 | 选图 | 办公 Agent 示例 |
| --- | --- | --- |
| 谁使用系统，可以做什么？ | 用例图 | 用户生成周报、修改文档或导出 PDF。 |
| 系统边界在哪，与谁交互？ | 系统上下文图 | 办公 Agent 接收用户任务，请求模型服务，向云文档平台保存结果。 |
| 系统内部怎么拆，各部分负责什么？ | 架构图、组件图 | 任务编排调用模型并调度工具，文件模块管理读写。 |
| 任务有哪些步骤，哪里分支或回退？ | 流程图、活动图 | 材料齐全就生成周报，缺少材料就追问。多人参与时可用泳道标明每步由谁负责。 |
| 一次请求中谁先调用谁，传什么、返回什么？ | 时序图 | 用户提交任务，Agent 请求模型，模型返回工具参数，Agent 执行工具并回传结果。 |
| 一个对象有哪些状态，什么事件改变状态？ | 状态图 | 任务从「执行中」进入「等待补充」，用户回复后继续执行。 |
| 数据从哪里来，怎么处理，最终存到哪？ | 数据流图（DFD） | 交互记录经过脱敏、清洗和质检，进入训练样本库。 |
| 存储哪些实体，实体怎么关联？ | 实体关系图（ER 图） | 一个会话有多个任务，一个任务有多条工具调用记录。 |
| 哪些类或接口参与，如何协作？ | 类图 | `ToolExecutor` 依赖 `Tool` 接口，文件工具和搜索工具实现该接口。 |
| 系统跑在哪里，服务怎么连？ | 部署图 | 客户端在 PC，编排服务在云端，通过推理接口调用昇腾集群。 |

## 接口和分支

- 节点优先写职责或读者认识的对象，例如「读取配置」「训练器」「验证指标」。边写动作、接口或传递的数据，例如「读取 `eval_args`」「返回验证分数」。技术缩写和符号首次出现时，把作用写在邻近说明中。
- 组件图以 `调用方 → 提供方` 表示调用，用真实方法名、路由、事件名或协议标注连线。图复杂时按要回答的问题拆开，静态分工与时间顺序分别用组件图和时序图。
- 图旁的接口说明应能独立阅读。复杂接口可用小表展示 `调用方 → 提供方`、实际入口、输入、返回或错误、状态影响与源码。小图可以用紧邻图的两三行说明。
- 区分同步回执、任务实际执行和持久化完成。把影响后续条件或调用方结果的返回画出来。每条不同结果的分支标出可判定条件。
- 让源码锚点和关系容易对应。将链接放在图的标题、对应图注或接口表中。节点上用短符号，长签名、字段结构和行号放到图外。

## 格式和呈现

- Mermaid 适合 Markdown 的流程、时序、状态与类型图。按语义选语法，检查节点标识、方向、引号、特殊字符、分组边界和闭合分支。可用现有渲染器时验证生成结果，并在阅读宽度内检查关键标签是否可读。
- 用户指定 HTML、SVG 或图片时，采用适合该输出的方式，优先保持图中文字可读，图旁保留可访问的说明及源码链接。宽图默认适应阅读宽度，密集内容按问题拆成数张完整的小图。
- 当前阅读器不能渲染图或缺少实际预览时，保留源码对应的简短说明，明确已做的是语法或静态检查。输出格式随交付需求选择。

## 代码百科存档模式的图示

- 优先采用阅读器可以直接绘制的基础语法。流程图和组件图用 `flowchart TD` 或 `flowchart LR`，节点写成 `A["入口"]`，条件写成 `B{"是否命中"}`，带标签的边写成 `A -->|读取| B`。
- 用例、系统上下文、架构、数据流、实体关系、类和部署可以用同一基础流程图语法画出对应的关系。上下文图标明内外部，活动图标明每步负责人，数据流图标明数据名称，实体关系图在边上标明基数，类图写清实现或依赖，部署图在节点标明运行位置、在边上标明协议。
- 时序图用 `sequenceDiagram`、`participant A as 入口`、`A->>B: 请求` 和 `B-->>A: 返回`。复杂条件用图旁的分支说明或单独的流程图。状态图用 `stateDiagram-v2`，例如 `state "已排队" as Queued`、`[*] --> Queued` 和 `Queued --> [*]: 取消`。
- 每行放一条语句，节点 ID 用英文字母、数字或下划线，标签用简短纯文本。将接口细节、源码标记和图例放在围栏外。较密集的图可以拆成独立视图。
