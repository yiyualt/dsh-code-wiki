# DSH 代码百科

DeepSeek Harness Web 插件。在侧栏打开「代码百科」可以阅读已有的 Wiki，生成新 Wiki 暂不可用。阅读器从 Markdown 的 `##` 标题生成章节目录，并展示存档的图示和源码引用。

## 打包和安装

```sh
npm pack
dsh plugin --profile web add ./dsh-code-wiki-0.20.0.tgz
```

也可以在 DSH 的「插件 → 添加插件」输入安装包的绝对路径，安装后启用。若 DSH 提示需要重启，请按原命令重启 Web 服务。

## 测试

需要 Node.js 22 或更高版本及 Git。在源码仓库根目录运行 `npm run check`，依次执行自动化测试、浏览器构建和安装包验证。安装包验证会在临时目录离线安装，检查发布文件清单、JavaScript 语法、模块入口及浏览器产物是否一致。

`npm test` 可单独运行自动化测试。文档与视频测试使用临时归档和模拟服务。

## 文档库

文档库打开当前 DSH profile 的 `dsh-code-wiki/documents/` 中保存的 Wiki。选择文档后，在左侧目录切换章节，窄屏可使用正文上方的「章节」选择器。点击正文中的源码引用可核对文件与行范围。

## 仓库介绍视频

打开一篇包含架构图的 Wiki，点击顶栏「视频」进入观看窗口。点击右上角 × 或按 Esc 可回到当前章节。有存档时可直接播放，无存档时可手动点击「生成视频」。新视频使用英文旁白，由模型根据仓库内容创作连续故事、7 至 10 个场景及 20 至 28 个画面拍点。

视频面向潜在用户介绍仓库的用途、需求、主要特性和架构。选题、导演、分场设计师和审片使用下方的模型选择规则。生成前读取固定提交的 README、README 链接中最多三份同仓库的概览或使用文档、已引用的源码以及静态图片；本地仓库仅使用归档资料。选题编辑根据这些证据确定受众、项目价值、一至三项主要特性和支撑它们的主要组件，并保留事实引用及内容取舍。没有项目原文依据时，不编造作者动机。

导演据此创作适合该仓库的介绍片，文案审核通过后才设计画面和生成配音。审核会检查事实依据、项目价值和叙事连贯性；偏成执行教程或存在不实陈述时，先重写一次，仍未通过则报告失败并保留旧视频。终端、数据表、图表、产品示意、源码和真实图片可组合使用，支持逐字输入、连线流动、数值变化、淡化和镜头聚焦。数值图表需要材料原文证据，组件连线保留经过验证的方向。关闭页面不会取消任务，重启 DSH 会中断未完成任务。选题依据、分镜与配音保存在当前 profile 的 `dsh-code-wiki/videos/` 中。删除文档会同时删除其视频。

英文配音使用 [GitDiagram 的 Charon 声线](https://github.com/ahmedkhaleel2004/gitdiagram/blob/main/src/server/explainer/voice.ts#L7-L31)。如果已有 `modelConfigFile`，且其中的 API 提供 Gemini 原生接口，插件可以用同一 API 调用 `gemini-3.1-flash-tts-preview`。插件只向已配置的同一主机发送英文讲稿。语音生成一条连续音轨，场景切换时间根据停顿估算。

界面使用 Charon 英语男声，默认语速约 140 词/分钟，通过保音高处理调整节奏。主题之间额外保留 0.5 秒停顿，画面与字幕沿用调整后的时轴。缺少凭据时，生成按钮下方会显示配置提示。语音执行失败时会显示错误，已有视频仍可播放。保存的语音元数据包含实测词数、语速和估算对齐标记。

需要使用 GitDiagram 同款模型 `google/gemini-3.8-flash-tts` 时，也可设置 `OPENROUTER_API_KEY`，或通过 `voiceConfigFile` 显式配置。显式配音设置优先于 `modelConfigFile`。讲稿和分镜继续使用 DSH 模型。

```json
{
  "url": "https://openrouter.ai/api/v1/audio/speech",
  "model": "google/gemini-3.8-flash-tts",
  "voice": "Charon",
  "api_key_env": "OPENROUTER_API_KEY"
}
```

打开文档、打开视频窗口、刷新或重新读取都不会自动生成视频。已有视频先显示封面，点击画面才开始播放。重新生成通过播放器工具栏发起，确认后开始；已有视频在新视频完成前仍会保留。

视频生成的总时限为 30 分钟，涵盖素材读取、选题、讲稿审核、分场设计、审片、配音和保存。达到上限时会明确显示超时错误，重新打开视频窗口仍可看到本次服务运行期间的失败原因。

后台服务日志以 `[dsh-code-wiki:video]` 标识视频任务，记录开始、阶段变化、分场进度、完成或终止原因；运行期间每 30 秒记录一次当前状态，包括任务编号、文档编号、总耗时和当前阶段耗时。日志不包含讲稿、分镜内容、音频或模型凭据。可在 DSH 服务的标准输出或其重定向日志中查看。

播放器支持点击画面播放或暂停、拖动进度、倍速、字幕开关、全屏和按场景跳转。方向键在进度条上前后跳转 5 秒，播放中跳转会继续播放。导出使用正常速度并包含字幕。字幕和组件出现时间会根据各段旁白时长估算。

「导出 MP4 / WebM」通过浏览器 Canvas、Web Audio 和 MediaRecorder 录制 1280×720、30 fps 视频，无需额外安装 FFmpeg 或浏览器。实际格式由浏览器支持情况决定，优先 MP4，否则 WebM。导出包含画面字幕和所选配音，耗时约等于视频时长；导出期间需保持页面可见，切到后台或关闭播放器会取消导出。文件保存到浏览器下载目录；源分镜与音频保存在 DSH，可再次导出。推荐使用新版 Chrome、Edge 或 Safari。

## 模型选择

普通安装直接使用 DSH 当前默认模型及其已配置的提供方、凭据和推理设置。每次生成读取当前选择，切换 DSH 默认模型后，下一次生成自动使用新模型。所选模型需支持函数工具调用。

需要为视频单独指定模型时，可在本机 Web profile 的 `cordis.patch.yml` 中设置 `modelConfigFile`。该配置优先于 DSH 默认模型，适用于个人 GPT 等兼容 Chat Completions 的服务。

```yaml
- id: dsh-code-wiki
  config:
    modelConfigFile: /path/to/config.local.json
```

插件从该文件的 `judge` 项读取 Chat Completions 端点、模型和凭据。配置了本地文件后，文件读取或模型调用失败会显示相应错误。移除 `modelConfigFile` 配置后，后续生成恢复使用 DSH 当前默认模型。
