# 本地文件夹生成代码百科

关联工单 [#3](https://github.com/yiyualt/dsh-code-wiki/issues/3)。

## 使用场景

用户通过现有「本地仓库」入口选择本地源码。当前流程要求找到 Git 仓库和提交，因而无法处理直接创建或从 ZIP 解压得到的普通目录。选中仓库子目录时，当前流程还会读取整个 Git 提交。

## 预期行为和范围

- 新建 Wiki 时，沿用「本地仓库」入口和文件夹选择器。选择 DSH 可访问的目录即可生成总览和目录，有无 Git 均可。
- 以所选目录为根读取磁盘上的当前源码和文档，包括尚未提交的文件和修改。引用显示相对于所选目录的文件路径和行号。
- 从文档库重新打开后，可以继续生成章节。每次生成章节都读取当时的文件，并用本次读取的内容核对引用。即使源码已编辑，用户也可以直接在原 Wiki 中生成新章节。此前生成的总览和章节可以继续阅读。
- 沿用现有源码类型和敏感路径规则。所选目录内的符号链接不可作为源码读取。目录无可用源码时，给出明确提示。
- 公开 GitHub 继续按提交读取。此前创建的本地 Git Wiki 继续使用文档保存的提交。

## 验收条件

1. 通过「本地仓库」选择一个没有 `.git`、包含两个相互引用源码文件的目录，生成总览和目录。从文档库重新打开并生成一章，核对正文引用的相对路径和行号。
2. 通过同一入口选择 Git 仓库的一个子目录。修改其中的一个源码文件且保留未提交状态，在所选目录之外放置另一个源码文件。核对生成时使用的是修改后的内容，且清单和引用仅涵盖所选子目录。
3. 在新建的本地 Wiki 生成总览后修改一处源码内容并移动其行号。重新打开原 Wiki，生成尚未生成的章节，核对新正文和引用使用修改后的内容与行号。原有总览和已生成章节仍可阅读。
4. 验证符号链接及匹配现有敏感路径规则的文件不可读取。没有可用源码的目录会返回明确提示。
5. 验证公开 GitHub 导入仍按提交读取。修改本地 Git 工作区源码，验证此前保存的 Git Wiki 仍能依据原提交生成章节。
