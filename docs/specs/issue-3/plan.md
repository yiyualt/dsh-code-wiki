# 本地文件夹实施方案

需求和验收条件见 [spec.md](spec.md)。

## 源码读取

- `read-repository.mjs` 为新建本地 Wiki 增加文件系统读取。沿用 `repositoryPath`，从所选目录列出相对路径，经同一 `paths` 和 `read` 接口提供给总览和章节生成。文件从磁盘按需读取，复用现有文件类型、敏感路径、文本和读取大小限制。
- 遍历时跳过符号链接，读取时再次校验文件是所选目录内的普通文件。目录扫描应有资源上限并响应请求取消。无可用源码时返回针对目录的提示。
- 保留 GitHub 提交和本地 Git 提交的读取方式，用于公开 GitHub 和已保存的本地 Git Wiki。

## 接口和存储

- 新建本地 Wiki 沿用 `source: 'local'`，以 `commit: null` 表示从目录读取当前文件。已有本地 Git 和 GitHub 文档沿用原有提交哈希，无须迁移。限定 `null` 只用于新格式的本地来源，保留旧格式及 GitHub 的哈希校验。
- 在 `index.js`、`src/wiki-storage.js` 和 `src/client.js` 接入这两种 `commit` 值。新建本地总览时从目录读取。按文档 ID 生成章节时使用保存的来源和 `commit`，直接提交章节上下文时使用请求中的对应字段。现有「本地仓库」和两种文件夹选择器继续使用，更新表单提示、README 和生成工具对源码来源的描述。
- 每次生成章节重新打开所选目录。总览中保存的路径和行号用于查找当前源码，新引用通过现有 `wiki_read` 的读到范围校验。如果原文件改名或行号变化，可用 `wiki_list` 查找当前文件。生成请求沿用现有文本缓存和无可用证据时的错误处理。

## 验证

- 文件读取测试覆盖没有 Git 的目录、Git 子目录里的未提交文件、相对路径、符号链接、敏感路径和空目录。
- 复用路由测试中的模拟作者，验证总览保存、重新打开、移动行号后读取并引用修改的源码，以及已有 Git 文档按提交生成。
- 在 Node.js 22 或更高版本运行 `npm run check`。通过 DeepSeek Harness Web 的现有入口验证普通目录的选择、总览生成、重新打开和章节生成，记录实际结果。
