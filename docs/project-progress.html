开源代码仓管理规范和纪律

实操大纲。以 DSH 代码百科仓库为例，逐节讨论许可、贡献、发布和维护。dsh-code-wiki

项目与许可 Issue 管理 分支、提交与 PR 评审与合并 版本与发布 维护与交接

01项目定位、许可与权限

  • README 写清项目用途、环境要求、安装方法和贡献入口。
  • 确认源码和依赖的许可，明确可公开的内容，以及维护者、合并者和发布者的权限。

仓库练习　对照 README 和 package.json，列出已说明的安装与使用条件、待确认的版权归属和许可。GitHub 许可指南

02Issue 与需求管理

  • 问题报告附环境、复现步骤、实际结果和预期结果，涉及账号、密钥或漏洞时使用合适的私下渠道。
  • 需求写明范围、优先级和验收条件。关闭 Issue 时记录处理结果。

仓库练习　按历史上的引用格式修复，写一条包含输入 Markdown、预期输出和验证方法的 Issue 草稿。历史修复

03分支、提交与 Pull Request

  • 从默认分支创建短期工作分支。每个提交围绕一个明确目标，提交信息说明改动。
  • PR 关联 Issue，说明修改范围、验证结果和影响。提交前检查 diff 与暂存区，只暂存当前改动所需的文件，并按仓库规则忽略本地配置和构建产物。

仓库练习　为一处文档修订创建分支，练习暂存、提交，再写一份附验收结果的 PR 说明。GitHub PR 指南

04评审、持续集成与合并

  • 评审对照验收条件，检查行为变化、回归测试和兼容性。
  • 确定默认分支的合并条件，包括审核、自动检查和合并权限。记录紧急改动的原因与补审安排。

仓库练习　在干净检出中用 npm ci 安装依赖，运行 npm run check，据此草拟 PR 的持续集成检查和合并条件。GitHub 分支保护

05版本、安装包与发布

  • 根据兼容性决定版本号，让 package.json、Git 标签、发布说明和安装包能对应到同一份代码。
  • 发布前核对打包清单，验证新装和升级，保留上一可用版本供回滚。

仓库练习　用现有 1.0.0 作为起点，在干净检出中检查 npm pack --dry-run 的文件清单，拟一份补丁版本的发布与安装验证步骤。GitHub 发布指南

06回滚、日常维护与交接

  • 区分撤销代码提交和恢复已安装版本，为两种操作分别记录步骤和验证方法。
  • 定期处理积压 Issue、跟踪依赖更新，记录维护责任、发布权限和交接事项。

仓库练习　以插件新版安装后侧栏无法打开为演练场景，拟出恢复上一安装包、复核侧栏和补做回归测试的步骤。
